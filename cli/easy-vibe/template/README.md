# Easy Vibe Project

本项目已接入 Easy Vibe，用固定目录组织业务代码、文档、规约、工作状态、数据和部署信息。

> Coding Agent 接入后必须先读取 [`guide/README.md`](guide/README.md)。

只有 `code/` 保存本项目的业务代码。`view/` 是 Easy Vibe 工作台资源，其他目录保存项目治理信息和业务产出，不应与业务源码混放。

Easy Vibe 提供默认协作方式，但不高于用户的明确要求。用户可以切换工作流、调整执行范围，或明确要求在工作流之外处理；Agent 应说明影响并记录偏离，不能仅以 Easy Vibe 规范为由拒绝用户。

`guide/` 和各目录中的 `README.md` 只提供简介与索引；执行、安全、目录、命名和 Step 规则统一以 `spec/` 为权威来源。

## 主要目录

- `code/`：业务代码。
- `docs/`：需求、设计、测试、会议、记录和 Bug 文档。
- `guide/`：Coding Agent 执行入口。
- `workflow/`：工作流以及 Step 的运行定义。
- `spec/`：全局规约以及与 Step 严格绑定的步骤规约。
- `status/`：工作状态和中断恢复信息。
- `command/`：项目自动化命令。
- `data/`：静态资源、下载内容和数据集。
- `deploy/`：环境、制品、运行时和运维信息。
- `agent/`：不同 Coding Agent 的适配入口。
- `view/`：Easy Vibe 本地工作台，不属于业务代码。

主工作表示独立的交付目标；完全独立的新工作或用户明确声明的新任务必须建立新的主工作。设计、开发、测试和修复等同一交付物的过程通常作为该主工作的子任务。边界不明确时，先询问用户，不得自行归类。

各目录的 `README.md` 是该模块的详细说明入口。
